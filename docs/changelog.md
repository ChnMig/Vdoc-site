# 变更记录

## v0.4.0-beta.1

项目仓库模型进入 Beta：用不可变提交、项目分支和发布引用替换默认草稿工作流，修订号及发布号由系统自动生成。支持连续历史、固定提交比较、合并审核与围绕明确改动的 AI 处理。详见 [提交与分支](admin-usage.md#commit-history)。

配套更新 Backend、Admin、MCP/Skill 与 Site，先在独立 Beta 数据库和存储中验证。旧内容通过明确的初始化与兼容映射保留，不能恢复已经缺失的旧草稿正文。稳定版与官网渠道保持隔离。

## v0.3.17

本轮 Beta 功能转为正式版，详见下方。先备份数据库及存储，配套更新 Backend／Admin（008–017 迁移）；更新 `:latest` 与官网。

以下为 Beta 历史，仅更新独立[测试环境](deployment.md#beta-channel)的 `:beta`。参见[手动升级](release-rollback.md)。

## v0.3.17-beta.25

## v0.3.14 {#v0-3-14}

- 严格校验布尔配置，拼写错误会阻止启动，避免误用内存模式；启动依赖和后台摘要任务可及时响应取消。
- AI Provider 测试取消、摘要和聊天请求被替代时，保留上游已返回的 Token 用量审计，旧结果不会覆盖新内容。
- 草稿修改和提交会提前拒绝已发布的同名版本；无变化保存复用既有对象，保留事务、审计和并发校验。
- 项目成员表单按项目及登录会话隔离，迟到的成功不会清空新输入；用户 Token 清单显示加载、失败、重试和空状态。
- 当前版本分享遇到发布竞态时重新读取一次最新版本；旧解锁凭证的下载错误不会污染新会话。
- MCP 错误数据递归脱敏，保留错误码和数据类型；成功的文档内容保持原样。
- Compose 使用独立连接字段传递 PostgreSQL 凭据，支持包含特殊字符的原始密码；官网排障跟随单文件部署，全局 MCP/Skill 安装使用校验后的发行包。

本次不新增应用数据库迁移，REST/MCP 工具参数保持兼容。升级前备份数据库和对象存储，保留账号、密钥及数据卷，更新镜像后重建容器；MCP/Skill 更新后重新加载 Agent 并重启 MCP。详见[升级与回滚](release-rollback.md)。

## v0.3.13 {#v0-3-13}

- 工作台请求在发起时绑定账号凭据，避免切换账号后旧操作使用新账号 Token；首次 AI 对话在退出、重新登录或离开页面后停止后续发送。
- 版本深链接不符合当前分支筛选时显示无效链接提示，避免停留在无法选择的状态。
- AI 结果因权限、配置变化或取消而作废时，失败审计保留上游已经返回的 Token 用量。
- 公开分享密码校验移到全局锁外，完成后重新检查权限及密码快照，避免校验期间阻塞其他请求。
- MCP 收到 HTTP 错误后及时截断响应并关闭连接，避免大错误页被误报为超时；异常值脱敏和固定提交安装失败处理更稳健。
- Skill 支持只修改草稿版本名或 changelog，同时保留读取到的正文和 revision。
- Docker 工作台通过自身 `/api` 代理访问后端，修复默认跨端口部署的登录和分享请求；同步中英文部署指引及发行锁。

本版不新增应用数据库迁移，REST/MCP 工具参数保持兼容。升级现有 Compose 时，将 `VDOC_ADMIN_API_BASE_URL` 改为 `same-origin`，保留账号、密钥和数据卷，再重新创建工作台容器。后端旧 `cors_allowed_origins` 配置已不生效；需要跨域浏览器 API 的部署应关闭内置 CORS 并在网关显式允许认证及分享请求头。详见[升级与回滚](release-rollback.md)。更新 MCP/Skill 包后重启 Agent。

## 当前产品面

- Backend 提供 public health/auth/docs/MCP routes 和 private Admin routes。
- Backend 在启用 database 时自动运行 migrations，在启用 storage 时会尝试创建缺失 bucket。
- Admin Docker 支持 runtime `VDOC_ADMIN_API_BASE_URL`，用于生成浏览器可用的 backend API base URL。
- `@vdoc/mcp` 是可安装 stdio MCP adapter，负责把 Agent MCP 请求转发到 backend。
- `Vdoc-skill` 是可安装 Agent 工作流包，要求 Agent 使用 Vdoc MCP 查询事实后再给结论。
- 后台 Admin AI 可以辅助解释 Draft、Version 和 Diff，但不替代外部 MCP/Skill Agent、机器 Diff 或人类发布门禁。
- Live E2E 使用 `./scripts/vdoc-e2e.sh live-compose --env-file ../.env`，只重置一次性 `VDOC_TEST_POSTGRES_DB`，默认 `vdoc_e2e`。

## 仍需记住的边界

- MCP 不能直接发布 Version。
- Agent 可以提交 Draft，发布必须由 Admin 或 SuperAdmin 审核。
- 不要把 Compose service name 用在浏览器配置里；浏览器使用 `127.0.0.1` 或域名，容器内部才使用 `postgres`、`rustfs`、`backend` 等服务名。
- 不要把真实 secret 写入文档、日志、截图或 Git history。
