# 首次使用

用一份 Markdown 团队约定，完成创建、审核发布和 Agent 查询。

## 开始前确认

- 已按 [部署指南](deployment.md#quick-start) 启动 Vdoc，并设置初始管理员账号。
- 工作台可以打开，Backend 健康检查的 `detail.healthy` 为 `true`。
- 用于接入的 Agent 支持 MCP stdio；运行 Agent 的机器已安装 Node.js 20 或更新版本、npm 和 Git。

首次查询成功后，再配置 Admin AI、公开分享和 Skill。

## 1. 登录并创建试用项目

打开[本机工作台](http://127.0.0.1:8081)，用部署时在 `docker-compose.yml` 设置的邮箱和密码登录；远程环境使用对应地址。

登录进入**工作空间**：左侧为团队／项目树，右侧列当前层级的团队、项目、文件夹或文档。初始 SuperAdmin 在**全部团队 → 创建团队**新建或选择团队，再点击**创建项目**，命名为 **Vdoc 试用**。创建表单均为弹窗。

项目内用**文档**浏览文件，**项目成员**查看成员。Project Admin／SuperAdmin 可在启用的项目中增删成员、分配 Reader／Writer／Project Admin 并访问**项目设置**。SuperAdmin 另有**团队设置**和**人员管理**。权限按项目分配，同团队不自动共享权限。

账号未设置时，返回[初始管理员配置](deployment.md#initial-admin)；修改初始化字段不重置已有账号。

设置分账号、外观、AI 配置、版本。外观选择主题／语言，AI 分系统默认／项目覆盖；切换分类或 AI 范围保留输入。标题旁**使用说明**可展开指引。

### 从工作空间进入文档

在项目的**文档**中逐级打开文件夹，点击文档进入独立阅读页：

| 区域           | 用途                                                                               |
| -------------- | ---------------------------------------------------------------------------------- |
| 左侧项目文件树 | 只显示当前项目的文件夹和文档；可返回工作空间、切换文件、新建文件夹或文档。         |
| 中间正文       | 查看当前选定的正式版本或草稿；上方切换分支、内容状态和具体版本。                   |
| 右侧目录与工具 | 点击正文标题定位；版本、差异、日志、文档 AI 各有独立入口，有权限时可打开文档设置。 |
| 文档顶栏       | 有权限时使用**分享**或**编辑草稿**；分享以当前选定的正式版本为目标。               |

单击文件夹行展开／收起并选择新建位置，不关闭文档。文档与文件夹位置分别标记；团队、项目、人员、文件夹及三种文档类型各用不同图标。

正文上方的紧凑信息区标明文件路径。Markdown 用带提示的图标切换**预览／源码**。OpenAPI 正式版本可切换**源码／接口**；接口列表支持搜索、分组、分页和详情，旧接口链接仍可定位。

阅读区右上角可**复制内容**、**下载源文件**，保留原文，不附加界面信息；空 TXT 也支持。顶栏切换主题／语言。后台与分享页共用阅读组件。

**日志**倒序记录文档／分支变更、草稿、提交、审核和发布，可加载更多；需文档读取权限，分享页不可见。

**版本**列各分支发布历史。**差异**选择两侧分支的正式版本或草稿，支持任意组合。源码按行标记增删、行号，可切统一／并排、展开上下文、下载原文；原语义变更保留。草稿比较读取当时已保存内容，修改后需重新比较，不写正式差异历史；大文件超限时提示下载。

**文档设置**分**文档信息**／**分支**标签页，切换保留输入；操作受角色和文档状态限制。

**文档 AI**独立开关：宽屏与正文并列，窄屏为侧栏弹窗，点击入口、关闭或 `Esc` 收起。摘要跟随所选修订；聊天可检索当前文档各分支的正式版本与已保存草稿，并区分来源。

窄屏**显示文件树**打开左侧抽屉，选文档后收起；**文档目录**打开弹窗，工具移至顶部。无标题时显示空目录提示。

工具切换保留阅读位置、预览／源码及输入。文档聊天跨阅读修订、侧栏开关和屏宽保留会话；切文档或账号清空。文件夹和项目页签局部更新，前进／后退恢复 URL；未保存内容仍需保存。

全局菜单保留**工作空间**、MCP、Skill、审计与设置入口。下拉及日期时间使用工作台组件；日期按设备本地时间选择，提交转 UTC。

### 修改自己的密码 {#change-password}

从文档页先返回工作空间，再点头像进入**设置 → 账号 → 修改密码**，输入当前密码、新密码及确认值。普通用户和管理员均可修改自己的密码。

新密码须不同于旧密码，为 12–72 个 UTF-8 字节，首尾无空白。成功后浏览器退出，需用新密码重登录；旧密码错误或确认不符时修正重试。

管理员忘记密码，由维护者[命令行重置](troubleshooting.md#reset-admin-password)。修改 `VDOC_INITIAL_ADMIN_PASSWORD` 不重置已有账号。

### 版本与检查更新 {#version-and-updates}

**设置 → 版本 → 版本与更新**显示前后端版本及渠道，Beta 有独立图标；版本／渠道不一致时提示检查部署配置。

点击**检查更新**才查询官方发布：后端为 Beta 则只查 Beta，稳定版只查正式版。新版本附发行说明，失败可重试；开发构建不支持检查。

此处仅提示，容器仍由维护者按[升级与回滚](release-rollback.md)手动更新。

## 2. 创建示例文档

在**工作空间**选择团队、项目、文件夹，点击**创建文档**；独立文档页可在左树选位置后点**新建文档**：

| 字段     | 示例值          |
| -------- | --------------- |
| 文档名称 | 团队约定        |
| 文档类型 | Markdown        |
| 文件名   | `team-guide.md` |
| 文件夹   | `docs`          |

名称用于展示，文件名单独保存：默认取名称或上传文件名，手动编辑后保留，后续上传不覆盖。选择项目根目录或文件夹，可无限层级新建，空目录保留。文件夹按项目隔离，团队隔离随项目归属。所选目录与文件名生成 `docs/team-guide.md`，无须手填路径；已有路径保留。

创建可上传 OpenAPI JSON/YAML、Markdown `.md` 或纯文本 `.txt`，生成未提交、未发布的 `dev` 草稿；本例先不上传。默认环境分支为 `dev`、`test`、受保护的 `prod`。管理员在**文档设置 → 分支**可建 `main`、`release/2026` 等安全名称，无须 `feature/` 前缀。

TXT 保留纯文本与换行，不渲染 Markdown／HTML，使用行差异；与 Markdown 共用草稿、审核、发布及 `doc:read`／`doc:draft` 权限流程。

## 3. 提交第一份草稿

打开文档，顶部选 `dev`／**草稿**，点**编辑草稿**进入**草稿编辑与审核**。版本填 `v1`，粘贴以下内容或上传 `.md`：

```md
# 团队约定

- 演示项目代号为 Northstar。
- 提交代码前，先运行项目测试。
- 文档修改先提交草稿，由项目管理员审核发布。
```

创建草稿后提交审核；仅保存不会成为 Agent 可读的已发布内容。

新草稿可选**起始分支／起始版本**并**载入源文件内容**后修改。已有内容须确认替换；切换选项不覆盖输入。顶部仍选择目标分支。

## 4. 审核并发布

选中 `v1` 草稿，点击**编辑草稿**，由 Project Admin／SuperAdmin 在**草稿编辑与审核**检查内容和 Diff，再批准发布。

顶部选**已发布**／`v1`，确认 `dev` 的三条约定。Version 不可变，修改需新草稿。文件树区分已发布、未发布草稿和空文档；版本、差异及 AI 用法见上文。

通过审核后打开实际发布版本；要求修改／拒绝保留草稿。历史支持已发布草稿只读快照，区分创建和真实发布时间；未发布不推测时间，仅待审核时显示审核输入。

**发布是人工动作。** MCP 可以提交草稿，不能直接发布 Version。

## 5. 创建读取令牌

在 MCP Token 页点击**创建 MCP 令牌**，建立用户绑定令牌：

- 选择 **`doc:read`** 读取 Markdown／TXT；本例不需草稿写权限。
- 确认用户可访问 **Vdoc 试用**，设置未来过期时间。
- 复制令牌到 Agent 的私密配置或密钥管理中。

有效令牌可在详情中再次查看／复制；列表、已撤销或过期令牌仅显示脱敏值。原始令牌不得进入命令参数、仓库、截图或日志。

## 6. 连接 Agent

按客户端选择格式；MCP Token 页面提供 Codex、Cursor 和 Claude Code 配置。

::: code-group

```json [Cursor / Claude Code]
{
  "mcpServers": {
    "vdoc": {
      "command": "npx",
      "args": [
        "--yes",
        "github:ChnMig/Vdoc-mcp#0b85872a4f1e7fdb4176dafa51fcaa5bbb8517a7"
      ],
      "env": {
        "VDOC_BASE_URL": "http://127.0.0.1:8080",
        "VDOC_MCP_TOKEN": "REPLACE_WITH_LOCAL_VDOC_MCP_TOKEN"
      }
    }
  }
}
```

```toml [Codex]
[mcp_servers.vdoc]
command = "npx"
args = ["--yes", "github:ChnMig/Vdoc-mcp#0b85872a4f1e7fdb4176dafa51fcaa5bbb8517a7"]
startup_timeout_sec = 60
tool_timeout_sec = 180

[mcp_servers.vdoc.env]
VDOC_BASE_URL = "http://127.0.0.1:8080"
VDOC_MCP_TOKEN = "REPLACE_WITH_LOCAL_VDOC_MCP_TOKEN"
```

:::

- **Codex：** 合并 TOML 到个人 `~/.codex/config.toml`，保存后重启 MCP 或新开会话，用 `/mcp` 查看。示例为首次 `npx` 下载预留 60 秒；见[官方 MCP 配置](https://developers.openai.com/codex/mcp/)。
- **Cursor：** 合并 JSON 到个人 `~/.cursor/mcp.json` 的 `mcpServers`，在 Settings → Tools & MCP 启用／重启。其他同格式客户端使用各自配置路径。
- **Claude Code：** JSON 合并到个人 `~/.claude.json` 顶层 `mcpServers`，保留其他服务；重启后用 `/mcp` 检查。含令牌配置勿写入共享 `.mcp.json`。见[官方说明](https://code.claude.com/docs/en/mcp-quickstart)。

保留已有服务器条目，令牌只存私密配置，不提交仓库。

用第 5 步令牌替换占位符，保存并重载 MCP。固定提交须匹配部署包 `workspace.lock.json` 的 `Vdoc-mcp`；当前未发布到 npm registry。

`VDOC_BASE_URL` 须从 **Agent 所在机器** 可达；仅同机可用 `127.0.0.1`，远程须用可达的 Backend 地址。选项见[MCP 接入与工具](mcp-tools.md)。

连接后应列出 `list_projects`、`list_documents`、`get_latest_doc`。

## 7. 让 Agent 读取文档

发送给 Agent：

```text
请先通过 Vdoc MCP，找到「Vdoc 试用」项目 dev 分支下
路径为 docs/team-guide.md 的最新已发布文档。
根据文档回答：项目代号是什么，提交代码前要做什么？
请注明文档路径、分支和版本；找不到时明确告诉我，不要自行补写。
```

核对：

- 实际调用 MCP 的 `get_latest_doc`，读取已发布内容。
- 回答含 **Northstar** 和**提交代码前先运行项目测试**。
- 引用 `docs/team-guide.md`、`dev`、`v1`；可用文档 ID 核源。

仅 `tools/list` 成功或回答相似，不能证明读过文档。

## 如果没有得到预期结果

| 现象                       | 下一步                                                                                    |
| -------------------------- | ----------------------------------------------------------------------------------------- |
| MCP 无法启动或连接         | 检查 Agent 机器上的 Node.js、npx、Git，以及 Backend 地址是否可访问；查看客户端 MCP 错误。 |
| 有工具，但找不到项目或文档 | 确认令牌仍有效、有 `doc:read`，关联用户可访问项目；核对文档路径和 `dev` 分支。            |
| 找到文档，但没有已发布版本 | 顶部选择草稿并批准发布，再切到正式版本确认已有 `v1`。                                     |
| Agent 没有查询就回答       | 确认 MCP 已启用，明确要求先调用 `get_latest_doc`；必要时新开会话重试。                    |

更多排查方法见 [故障排查](troubleshooting.md)。

## 查询成功后，再按需要配置

- **持续协作：** [Vdoc Skill](skill-workflows.md#安装) 引导 Agent 在集成、迁移分析和修改前查询 Vdoc；实时内容仍来自 MCP。
- **接口变更：** 创建 OpenAPI 3.0／3.1 文档，审核发布两版，按[示例](how-it-works.md#example)查 Diff；需 `api:read`。
- **AI 助手：** 按 [Admin AI](admin-ai.md) 配置 OpenAI-compatible 提供商，启用摘要／聊天。AI 不能批准、拒绝、修改或发布；缺配置或调用失败不阻塞人工审核。
- **公开分享：** 见下文。
- **发布验证：** 见[工程验证与发布检查](deployment.md#engineering-and-release-checks)。

### 创建和管理公开分享

Project Admin／SuperAdmin 在文档顶部选正式版本，点**分享**，核对文档、分支、版本后建链接。链接固定当前版本，后续发布不改变内容；草稿不能分享。已有“最新／全部版本”链接沿用原范围。

有效期默认三个月，可选一／六个月、一年或永久。可选密码为 12–72 个 UTF-8 字节，首尾无 Unicode 空白。复制完整能力链接，可再次显示或不可逆撤销。列表分有效、过期、撤销；换项目／文档清除已显示链接及未提交密码。

分享页沿用上述阅读功能；手机点目录按钮。OpenAPI／TXT 显示原文，项目树、内部日志、AI 和管理工具隐藏。
