# 首次使用

发布一份团队约定，让 Agent 从 Vdoc 读取它。完成后，你会看到一条真实查询：Agent 读取已发布的 Markdown，并根据文档回答问题。

## 开始前确认

- 已按 [部署指南](deployment.md#quick-start) 启动 Vdoc，并设置初始管理员账号。
- 工作台可以打开，Backend 健康检查的 `detail.healthy` 为 `true`。
- 用于接入的 Agent 支持 MCP stdio；运行 Agent 的机器已安装 Node.js 20 或更新版本、npm 和 Git。

这次用一份 Markdown 完成“创建 → 审核发布 → 查询”。Admin AI、公开分享和 Skill 可以在首次查询成功后配置。

## 1. 登录并创建试用项目

打开 [本机工作台](http://127.0.0.1:8081)，用部署时在 `docker-compose.yml` 中设置的邮箱和密码登录。如果使用远程环境，请打开对应的工作台地址。

登录后进入**工作空间**。左侧是团队与项目树，右侧按当前层级展示团队、项目，或项目内的文件夹和文档。用初始 SuperAdmin 在**全部团队**点击**创建团队**，或选择已有团队；进入该团队后，点击**创建项目**，创建名为 **Vdoc 试用** 的 Project。创建表单以弹窗打开。

选中项目后，**文档**用于浏览文件夹和文件，**项目成员**用于查看成员；Project Admin 或 SuperAdmin 可在启用的项目中添加成员、调整 Reader／Writer／Project Admin 角色或移除成员，并访问**项目设置**。SuperAdmin 还可在工作空间打开**团队设置**和**人员管理**。人员访问权限按项目分配，不会因为属于同一团队就自动获得其他项目的权限。

账号尚未设置时，返回 [初始管理员配置](deployment.md#initial-admin)。已有数据库时修改初始化字段不会重置账号。

设置分账号、外观、AI 配置、版本。外观切换主题/语言，AI 分系统默认/项目覆盖；切换分类或 AI 范围保留未保存输入。其他页面点击标题旁**使用说明**展开指引。

### 从工作空间进入文档

在项目的**文档**中逐级打开文件夹，点击文档进入独立阅读页：

| 区域           | 用途                                                                         |
| -------------- | ---------------------------------------------------------------------------- |
| 左侧项目文件树 | 只显示当前项目的文件夹和文档；可返回工作空间、切换文件、新建文件夹或文档。   |
| 中间正文       | 查看当前选定的正式版本或草稿；上方切换分支、内容状态和具体版本。             |
| 右侧目录与工具 | 点击正文标题定位；版本、差异、文档 AI 各有独立入口，有权限时可打开文档设置。 |
| 文档顶栏       | 有权限时使用**分享**或**编辑草稿**；分享以当前选定的正式版本为目标。         |

文件夹整行单击展开或收起，同时选择新建位置，不会关闭当前文档。选中文档与文件夹位置分别显示；团队、项目、人员、文件夹都有各自图标，OpenAPI、Markdown、TXT 也使用不同文件图标。

**版本**列出当前文档各分支的发布历史，选中后阅读对应版本。独立的**差异**工具分别选择源／目标分支及正式版本，支持同文档内同分支或跨分支比较，不接受草稿。方向为源到目标；改分支后重选该侧版本。已有结果自动加载，否则点击**比较**。

**文档设置**内分**文档信息**与**分支**标签页，切换保留未保存输入；操作受项目角色及文档状态限制。

**文档 AI**可独立开关：宽屏右侧与正文／工具并列，窄屏为右侧模态面板，关闭恢复原位置。再次点击入口、关闭按钮或在面板内按 `Esc` 收起。摘要和聊天针对顶部所选版本或草稿。

窄屏通过**显示文件树**打开左侧抽屉，选中文档后自动收起；**文档目录**以弹窗打开，工具入口移到顶部。没有标题的正文会显示无目录提示。

切换工具再返回正文，保留阅读位置及预览／源码选择，已访问工具保留输入。同一阅读目标的 AI 输入在关闭、重开或跨屏宽切换时保留；更换分支、版本或草稿建立新上下文。文件夹和项目标签页局部更新，前进／后退恢复地址中的选择。这些临时状态仅限当前文档、项目和登录会话，不替代保存。

全局菜单将这些浏览与管理入口合并为**工作空间**；MCP、Skill、审计和设置继续单独提供。项目等下拉与日期时间选择使用工作台组件；日期时间按设备本地时间选择，提交时转换为 UTC。

### 修改自己的密码 {#change-password}

登录后，如在文档页先返回工作空间，再点击右上角头像进入**设置**，选择**账号 → 修改密码**，输入当前密码、新密码和确认新密码。普通用户和管理员都可以修改自己的密码。

新密码必须与当前密码不同，长度为 12–72 个 UTF-8 字节，且首尾不能有空白字符。提交成功后，当前浏览器会退出登录，请使用新密码重新登录。当前密码不正确或两次新密码不一致时，按表单提示修正后重试。

忘记管理员密码时，由服务器维护者使用[命令行重置](troubleshooting.md#reset-admin-password)。修改 Compose 中的 `VDOC_INITIAL_ADMIN_PASSWORD` 不会重置已有账号。

### 版本与检查更新 {#version-and-updates}

登录后进入**设置 → 版本**，在**版本与更新**查看当前部署的前端版本、后端版本和更新渠道。Beta 部署使用独立 Beta 图标。前后端版本或渠道不一致时，页面会提示检查部署配置。

点击**检查更新**才会查询官方发布信息；查询渠道由当前后端版本决定。Beta 仅检查 Beta 测试版，稳定版仅检查正式版。可用新版本会附带发行说明链接；检查失败时可以重试。开发构建不支持发布版本检查。

此功能只检查和提示，更新容器仍需维护者按[升级与回滚](release-rollback.md)手动执行。

## 2. 创建示例文档

在**工作空间**依次打开团队、项目和目标文件夹，点击**创建文档**；在独立文档页，也可从左侧文件树选择位置后点击**新建文档**：

| 字段     | 示例值          |
| -------- | --------------- |
| 文档名称 | 团队约定        |
| 文档类型 | Markdown        |
| 文件名   | `team-guide.md` |
| 文件夹   | `docs`          |

文档名称用于展示；文件名单独保存，未手动修改时默认带入名称，也可由上传文件带入原文件名；手动修改后保留你的文件名。在文件夹树选择项目根目录或已有目录，也可在任意目录下新建子文件夹，空文件夹会保留，不设固定层级上限。文件夹按项目隔离，团队通过项目归属隔离。示例位置为 `docs/team-guide.md`，完整相对路径由所选文件夹和文件名生成，不再手填；已有路径继续保留。

创建时可选上传 OpenAPI JSON/YAML、Markdown `.md` 或纯文本 `.txt`，内容保存为 `dev` 上的初始草稿，不会自动提交或发布。为继续下面的示例，此次先不上传。默认 `dev`、`test`、受保护的 `prod` 是环境分支；管理员也可在**文档设置 → 分支**创建 `main`、`release/2026` 等安全自定义名称，无须 `feature/` 前缀。

TXT 使用纯文本预览，保留换行，`#`、链接和 HTML 不会被当作 Markdown 渲染；版本比较使用行差异。TXT 与 Markdown 沿用相同的草稿、审核、发布及 `doc:read` / `doc:draft` 权限流程。

## 3. 提交第一份草稿

点击这份文档进入独立页面，顶部选择 `dev` 和**草稿**，点击顶栏的**编辑草稿**进入**草稿编辑与审核**。版本名称填 `v1`，在内容输入框粘贴以下 Markdown，也可以保存为 `.md` 文件上传：

```md
# 团队约定

- 演示项目代号为 Northstar。
- 提交代码前，先运行项目测试。
- 文档修改先提交草稿，由项目管理员审核发布。
```

这是用于试用的示例内容。创建草稿（Draft）后，执行提交审核；仅保存草稿还不能让 Agent 把它当作已发布文档。

## 4. 审核并发布

顶部选择刚提交的 `v1` 草稿，点击**编辑草稿**，在**草稿编辑与审核**中检查内容和 Diff，然后批准发布。由 Project Admin 或 SuperAdmin 完成这一步。

顶部切到**已发布**并选择 `v1`，确认 `dev` 下能读到三条约定。这是不可变版本（Version），后续修改需要新草稿。独立的**版本**入口查看发布历史，**差异**入口选择两侧分支和正式版本进行比较；可随时展开**文档 AI**，针对顶部选定内容查看摘要和聊天。文件树区分已发布、有未发布草稿和空文档。

**发布是人工动作。** MCP 可以提交草稿，不能直接发布 Version。

## 5. 创建读取令牌

打开 MCP Token 页面，点击列表标题旁的**创建 MCP 令牌**，创建用户绑定的令牌：

- 选择 **`doc:read`**，用于读取 Markdown 或 TXT；这次查询不需要草稿写入权限。
- 确认令牌关联用户可以访问 **Vdoc 试用** 项目，并设置未来的过期时间。
- 复制令牌到 Agent 的私密配置或密钥管理中。

有效令牌可在详情中再次查看和复制；列表、已撤销或已过期的令牌只显示脱敏值。不要将原始令牌放进命令行参数、仓库、截图或日志。

## 6. 连接 Agent

选择客户端对应的配置格式。工作台的 MCP Token 页面也能生成这两种配置。

::: code-group

```json [Cursor]
{
  "mcpServers": {
    "vdoc": {
      "command": "npx",
      "args": [
        "--yes",
        "github:ChnMig/Vdoc-mcp#35a60d23963aec29832b4da059081883d195bef3"
      ],
      "env": {
        "VDOC_BASE_URL": "http://127.0.0.1:8080",
        "VDOC_MCP_TOKEN": "REPLACE_WITH_LOCAL_VDOC_MCP_TOKEN"
      }
    }
  }
}
```

```toml [Codex]
[mcp_servers.vdoc]
command = "npx"
args = ["--yes", "github:ChnMig/Vdoc-mcp#35a60d23963aec29832b4da059081883d195bef3"]
startup_timeout_sec = 60
tool_timeout_sec = 180

[mcp_servers.vdoc.env]
VDOC_BASE_URL = "http://127.0.0.1:8080"
VDOC_MCP_TOKEN = "REPLACE_WITH_LOCAL_VDOC_MCP_TOKEN"
```

:::

- **Codex：** 将 TOML 节合并到个人 `~/.codex/config.toml`，保存后重启 Vdoc MCP 服务或新开会话，使用 `/mcp` 查看连接。首次 `npx` 启动可能需要下载，示例预留了 60 秒启动时间。参阅 [官方 MCP 配置说明](https://developers.openai.com/codex/mcp/)。
- **Cursor：** 将 JSON 合并到个人 `~/.cursor/mcp.json` 的 `mcpServers` 中，在 Settings → Tools & MCP 中启用或重启 Vdoc。其他使用 `mcpServers` 的客户端可复用 JSON，但配置位置以对应客户端为准。

只修改自己的私密配置，保留已有服务器条目；不要把令牌提交到项目仓库。

将占位符替换为第 5 步的令牌，保存到客户端的私密配置中，然后重新加载 MCP 连接。这里使用官方 GitHub 仓库的固定提交，版本须与部署包 `workspace.lock.json` 中的 `Vdoc-mcp` 一致；当前包尚未发布到 npm registry。

`VDOC_BASE_URL` 必须能从 **Agent 运行的机器** 访问。`127.0.0.1` 只适用于 Agent 和 Backend 在同一台机器上；远程 Agent 请使用它能访问的 Backend 地址。完整选项见 [MCP 接入与工具](mcp-tools.md)。

客户端应显示 Vdoc 工具已连接，工具清单中应有 `list_projects`、`list_documents` 和 `get_latest_doc`。

## 7. 让 Agent 读取文档

把下面这句话发送给 Agent：

```text
请先通过 Vdoc MCP，找到「Vdoc 试用」项目 dev 分支下
路径为 docs/team-guide.md 的最新已发布文档。
根据文档回答：项目代号是什么，提交代码前要做什么？
请注明文档路径、分支和版本；找不到时明确告诉我，不要自行补写。
```

检查这三个结果：

- Agent 实际调用了 Vdoc MCP，并使用 `get_latest_doc` 读取已发布内容。
- 回答包含示例中的 **Northstar** 和 **提交代码前先运行项目测试**。
- 引用的是 `docs/team-guide.md`、`dev` 分支和已发布的 `v1`；文档 ID 也可用于核对来源。

这次查询成功后，你就完成了从人工审核到 Agent 使用文档的第一条流程。只看到 `tools/list` 成功，或 Agent 给出了相似回答，都还不能证明它读到了这份文档。

## 如果没有得到预期结果

| 现象                       | 下一步                                                                                    |
| -------------------------- | ----------------------------------------------------------------------------------------- |
| MCP 无法启动或连接         | 检查 Agent 机器上的 Node.js、npx、Git，以及 Backend 地址是否可访问；查看客户端 MCP 错误。 |
| 有工具，但找不到项目或文档 | 确认令牌仍有效、有 `doc:read`，关联用户可访问项目；核对文档路径和 `dev` 分支。            |
| 找到文档，但没有已发布版本 | 顶部选择草稿并批准发布，再切到正式版本确认已有 `v1`。                                     |
| Agent 没有查询就回答       | 确认 MCP 已启用，明确要求先调用 `get_latest_doc`；必要时新开会话重试。                    |

更多排查方法见 [故障排查](troubleshooting.md)。

## 查询成功后，再按需要配置

- **让 Agent 持续按文档协作：** 安装 [Vdoc Skill](skill-workflows.md#安装)。它引导 Agent 在接口集成、迁移分析和文档修改前先查 Vdoc；实时内容仍来自 MCP。
- **体验接口变更：** 创建 OpenAPI 文档（支持 OpenAPI 3.0 / 3.1），提交并审核两个版本，按 [接口变更示例](how-it-works.md#example) 查询 Diff。令牌需有 `api:read`。
- **启用后台 AI 助手：** 按 [Admin AI](admin-ai.md) 配置 OpenAI-compatible 提供商，可使用自动摘要和页面内对话。它不能批准、拒绝、修改或发布文档；配置缺失或调用失败不阻塞人工审核。
- **向项目外分享文档：** 按下面的说明创建公开链接。
- **验证发布候选：** 维护者可继续执行 [工程验证与发布检查](deployment.md#engineering-and-release-checks)。

### 创建和管理公开分享

在独立文档页，Project Admin 或 SuperAdmin 在顶部选好正式版本后，点击顶栏的**分享**打开弹窗，核对文档、分支与版本，再创建链接。链接固定到当前显示的版本；以后发布新版也不会改变链接内容。草稿不能公开分享。已有“最新版本”或“全部版本”链接继续遵循原范围。

默认有效期三个月，也可选一个月、六个月、一年或永久。可选密码须为 12–72 个 UTF-8 字节，首尾不能有 Unicode 空白。创建后复制完整能力链接，可再次显示或不可逆撤销。列表区分有效、过期、撤销；切换项目或文档会清除当前显示的能力链接和未提交密码。
