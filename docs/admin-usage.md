# 首次使用

本页使用 `v0.4.0-beta.3` 的文档独立分支模型，完成保存、审核发布和 Agent 查询。请使用独立的 [Beta 环境](deployment.md#beta-channel)。

## 开始前确认

- 按[部署指南](deployment.md#quick-start)启动 Vdoc，设置初始管理员，并确认健康检查的 `detail.healthy` 为 `true`。
- Agent 支持 MCP stdio；其所在机器已安装 Node.js 20 或更新版本、npm 和 Git。

## 1. 登录并创建试用项目

打开[本机工作台](http://127.0.0.1:8081)或部署地址，用 Compose 中的账号登录。初始 SuperAdmin 在**工作空间 → 全部团队**创建团队，再创建 **Vdoc 试用**项目。**文档**浏览文件，**项目成员**管理 Reader／Writer／Project Admin；权限按项目分配，同团队不自动共享。

账号未设置时返回[初始管理员配置](deployment.md#initial-admin)；修改初始化字段不重置已有账号。

## 2. 新建文档

进入项目的**文档**列表，点击**新建文档**。选择 Markdown，名称填**团队约定**，路径为 `docs/team-guide.md`。初始分支默认 `main`，也可以手动填写 `dev` 等名称。创建时上传或填入：

```md
# 团队约定

- 演示项目代号为 Northstar。
- 提交代码前，先运行项目测试。
- 文档修改保存为版本，经管理员审核后发布。
```

也可创建 OpenAPI JSON/YAML 或 TXT 文档。TXT 保留原文与换行，不执行 HTML。文档创建成功后即有 `main.1`；如果初始分支填写 `dev`，则为 `dev.1`。每份文档有自己的分支和历史，不继承其他文档的分支。

## 3. 保存、比较与分支 {#commit-history}

打开文档，标题下的**文档分支**选择当前分支，**版本**选择要阅读的历史。点击**编辑**，修改后**保存版本**：`main.1` 的下一次有变化的保存为 `main.2`，再下一次为 `main.3`。编号由系统生成，不需要手动填写；提交说明可选。

点击分支选择旁的**新建分支**，输入 `dev`。新分支从当前查看的版本开始，保留来源历史；第一次新保存为 `dev.1`，下一次为 `dev.2`。另一份文档的 `dev.1` 独立计数。切换分支不改变左侧项目文档目录，也不影响其他文档。

**版本历史**可打开某次原文；**比较**选择同一文档的两个固定版本。OpenAPI 还显示可用的语义和 Breaking Change 检查。还原操作追加新版本，保留原历史。编辑器也可从同类型文件导入正文，导入只修改当前文档。

别人先保存时，提示会保留本地输入；可以比较后协调，或把修改保存到新分支。网络异常后原样重试不会重复创建版本。失败、无变化和重试不会消耗编号。未保存的编辑按文档与分支保留。

## 4. 审核并发布

`main` 默认可直接编辑。需要协作审核时，在右侧工具栏的**合并请求**中选择当前文档的来源和目标分支，查看实际合并结果，再由管理员审核。分支发生变化后必须重新审核；冲突解决也创建新的审核轮次。

保存、合并和发布是独立操作。在右侧工具栏的**发布记录**中，由管理员确认并发布当前版本。发布沿用 `main.2` 等可读版本名并生成独立发布 ID；后续保存不改变已经发布的正文。MCP 可以保存版本、比较和发起合并请求，不能批准、合并或绕过人工发布。

## 5. 创建读取令牌

在 MCP Token 页点击**创建 MCP 令牌**，选择 Markdown／TXT 所需的 `doc:read`，确认关联用户可访问 **Vdoc 试用**，设置未来过期时间。原始令牌只存 Agent 私密配置或密钥管理，不进入仓库、命令参数、截图和日志。有效令牌可再次查看／复制；过期、撤销和列表仅显示脱敏值。

## 6. 连接 Agent

按[MCP 渠道安装指引](mcp-tools.md#release-channels)安装 Beta adapter，再从令牌页复制 Codex、Cursor 或 Claude Code 对应配置。现有配置保留其他服务器条目；`VDOC_MCP_TOKEN` 填本人的令牌，`VDOC_BASE_URL` 必须从 **Agent 所在机器**可达，只有同机部署才能用 `127.0.0.1`。

安装后重启 MCP／Agent 会话并刷新工具发现。应列出 `list_projects`、`list_releases`、`get_release`、`get_document_at_commit`；完整配置和固定提交安装方式见[MCP 接入与工具](mcp-tools.md)。MCP 与 Skill 必须来自同一渠道和发行包，当前不发布到 npm registry。

## 7. 让 Agent 读取文档

发送给 Agent：

```text
请通过 Vdoc MCP 找到「Vdoc 试用」项目中的「团队约定」文档，
再找到这份文档 main 分支的最新发布记录，
将发布记录解析为固定 commit_id，读取其中 docs/team-guide.md 的正文。
项目代号是什么，提交代码前要做什么？
请注明路径、分支、发布 ID 和 commit_id；找不到时明确告诉我，不要补写。
```

核对先用 `list_documents` 找到文档，后续工具始终传入该 `document_id`，再调用 `list_releases`／`get_release`，再以该发布的 `commit_id` 调用 `get_document_at_commit`。回答应包含 **Northstar** 和**提交代码前先运行项目测试**。仅 `tools/list` 成功或答案相似不证明读过文档，也不要用未发布 HEAD 冒充发布内容。

连接失败先检查 Agent 机器的运行环境、Backend 地址和客户端错误；无文档则核对令牌有效期、`doc:read`、用户权限及发布记录。更多方法见[故障排查](troubleshooting.md)。

## 阅读、AI、分享与事件

文档页沿用左侧项目目录、中间正文、右侧大纲与工具的布局。历史、比较等入口在右侧工具栏，手机从顶部“文档工具”菜单进入。AI 在独立侧栏打开，不替换正文；手机使用弹窗。可复制或下载当前原文，Markdown 可切预览／源码。旧 OpenAPI 接口列表及保存的版本链接仍可读取。

**AI 分析**手动选择一个提交或固定提交对。分析 C1→C2 时出现 C3，结果仍属于 C1→C2，保留输入指纹、模型与状态。证据最多 32 个文档、128 KiB，并标记截断；失败不丢失提交，也不自动生成、应用补丁或批准发布。配置见[Admin AI](admin-ai.md)。

### 创建和管理公开分享

点击顶部**分享**，为当前已发布版本创建固定分享；尚未发布时先按提示审阅发布。也可在**发布记录**中分享某次发布，支持密码、到期、再次显示和撤销。可选密码须为 12–72 个 UTF-8 字节，首尾无 Unicode 空白。后续提交不改写分享正文；匿名读者不见项目树、内部日志或 AI。原有公开链接保留既定范围和访问规则。

管理员可订阅持久化事件，默认发布事件，也可显式选择内部提交。站内订阅显示投递账本；Webhook 需验证签名，按事件 ID 去重并处理乱序。投递可暂停、重试，失败不会撤销提交。Git 风格指提交图、分支和合并，不提供原生 `git clone`／`git push` 协议。

## 已有项目与兼容读取

打开已有文档时，系统建立该文档的独立分支与历史，保留来源记录；原项目提交、旧正式版本和现存草稿不被覆盖。内部 `legacy/...` 引用不出现在正常分支选择器中。旧版历史入口继续定位原文档，已有公开分享继续可读。已被覆盖且无存留正文的旧保存无法恢复。

转换后的文档，其旧内容写接口被拒绝，客户端应升级到提交工具。明确旧版本／草稿 URL 在工作台只读，继续定位原对象，不自动改到 HEAD；旧聊天和历史比较仍属旧快照。`get_latest_doc` 等兼容工具用于未转换的旧模型，新的发布读取按上文固定提交。

## 账号和版本设置

### 修改自己的密码 {#change-password}

从文档页先返回工作空间，再通过左侧栏底部的账户菜单进入**设置 → 账号 → 修改密码**，输入当前密码、新密码及确认值。普通用户和管理员均可修改自己的密码。

新密码须不同于旧密码，为 12–72 个 UTF-8 字节，首尾无空白。成功后浏览器退出，需用新密码重登录；旧密码错误或确认不符时修正重试。

管理员忘记密码，由维护者[命令行重置](troubleshooting.md#reset-admin-password)。修改 `VDOC_INITIAL_ADMIN_PASSWORD` 不重置已有账号。

### 版本与检查更新 {#version-and-updates}

**设置 → 版本 → 版本与更新**显示前后端版本及渠道，Beta 有独立图标；版本／渠道不一致时提示检查部署配置。

点击**检查更新**才查询官方发布：后端为 Beta 则只查 Beta，稳定版只查正式版。新版本附发行说明，失败可重试；开发构建不支持检查。

此处仅提示，容器仍由维护者按[升级与回滚](release-rollback.md)手动更新。

## 审计历史

动作和资源使用可读枚举筛选及展示。操作者支持按邮箱模糊查询或用户 ID 精确查询，在后端分页前筛选。列表显示操作者邮箱和项目名，悬停可查看原始 ID；系统操作、匿名访客及已删除对象有明确说明。项目管理员仍只能查看自己管理的项目。
